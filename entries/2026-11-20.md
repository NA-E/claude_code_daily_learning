**WORKFLOW — The Claude Code team's "make the agent prove its work" setup: end-to-end test, property test, old-vs-new diff, 3 fix rounds max.** Source: The Neuron (AI Skill of the Day). (1) An end-to-end test of one real user flow. (2) A property-based test of a rule that should always hold (for example, "balance never goes negative") run against thousands of generated inputs. (3) When replacing old code, run the old and new versions on the same inputs and have the agent chase down any differences. Claude gets up to three rounds to fix failing checks before it hands off to a human, and it's never allowed to edit the checks that judge it. Prompt: `Make this change: [describe it]. Before editing, tell me how you will verify [expected behavior]. After the change, run an end-to-end test of that flow plus a test of one rule that should always hold, and report the actual results. If a check fails, fix it up to three times, then stop and tell me. Do not edit the tests to make them pass, and flag anything you could not test.` Why it matters: it's the grader-gaming fix (11-18) as a working default. Who: anyone handing Claude Code multi-file changes. Action: add the last two sentences to your CLAUDE.md.

**NEWS — Railway's hack postmortem: an attacker using an AI model with no safeguards went from build sandbox to decrypted customer AI keys in 12 steps over about 24 hours.** Source: The Pragmatic Engineer (Gergely Orosz). Phase 2 (11 hours): a file-read bug on the build system, then stolen build credentials, then a Temporal cluster, then the monorepo downloaded. Phase 3 (10 hours): a misconfigured OpenID Connect binding gave a short-lived cloud credential, which led to a long-lived one and then an SSH key. Phase 4 (3 hours): encrypted environment variables decrypted through the key-management service. Six hours after getting the code, the attacker had a plan to reach the keys. Railway sent hashes of the leaked keys to the AI providers so they could revoke them. Northflank, which had published "How to migrate off Railway," was hacked the same way 9 days later and took 9 hours to detect it. Railway's fixes: one throwaway VM per build, 2FA or biometrics for sensitive secrets, design as if attackers already have your source code, and shut down old systems. Why it matters: AI keys are now what attackers are after. Who: anyone keeping Anthropic or OpenAI keys in a PaaS such as Railway, Vercel or Render. Action: set a monthly spend limit in console.anthropic.com and rotate any key that has been in a hosted environment variable.
