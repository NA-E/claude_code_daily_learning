**CONCEPT — Every's cache bug: Slack IDs in memory-folder names made every user's system prompt different, so prompt caching silently never hit.** Source: Every, "Building a More Efficient Agent" (Laura Entis). Engineer Paridhi Agarwal cut token costs by more than 80% across 11 frequent tasks through a model upgrade, reading less data per tool call and deferred tool loading. The biggest single find, made with Opus 5.5, was the cache bug: Claude adds memory-folder names to the system prompt, Every's contained each user's Slack ID, and the text must be identical to be reused. Fix: give every memory folder the same generic name and keep Slack IDs out of the model's view. Best-case test result: 74% lower token cost. Also: routing everything through a cheap Sonnet coordinator that hands hard jobs to Opus raised costs, because requests were often processed by both models. Why it matters: it is a concrete checklist for any agent with a long system prompt. Action: print your agent's system prompt and check for per-user or per-run values (IDs, timestamps, names) that break caching.

**NEWS — Sonnet 5.5 migration: one agent loop fell 86% per closed task, from $3.76 to $0.51.** Source: Creators AI Substack, "How I stopped overpaying for AI Models" (thecreatorsai.com/p/choose-ai-models-cheaper-every-month). The loop (ShopClaw) ran on Opus 4.8 plus Sonnet 4.5 for over 2 months. After moving to Sonnet 5.5 only, the author measured 7.5 days before and 3 days after, repriced at API list rates. Of the 86%, price accounts for 42% ($3.76 to $2.19) and lower volume for another 76% ($2.19 to $0.51): 5.6x fewer cache reads, 3.7x fewer turns per run, and 0 of 32 runs hit the turn limit versus 17 of 103 before. Caveats the author states: API-equivalent cost not cash, a 3-day after-window (62 tasks), a shifted task mix, and quality measured only by log status. Why it matters: it supports 10-06's point that price per token is the wrong unit. Action: pull your own before/after turn counts, not just token prices.
