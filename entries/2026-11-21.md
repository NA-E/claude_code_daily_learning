**WORKFLOW — Why agents pick the wrong tool: the model sees only the name, description and parameter list, never your code.** Source: AI Agents Simplified. Anthropic measured five common MCP servers: 58 tools took about 55,000 tokens before the task began, and the GitHub server alone (35 tools) took about 26,000. Research results: LongFuncEval reports a 7%–85% performance drop as the tool count grows. RAG-MCP (not peer reviewed) found correct picks went from 13.62% with every tool loaded to 43.13% when only likely candidates were passed in. OpenAI's guide suggests fewer than 20 functions per turn. Anthropic's tool search lifted Claude Opus 4 from 49% to 74% on its internal MCP evals, while Arcade's independent test with 4,027 tools found the right tool in the results 56%–64% of the time. The fixes: add a system prefix to each tool name (`crm_search` vs `auth_find_account`), add a "use this for X, not for Y" line (about 20 tokens), merge near-duplicate tools, spell out ID formats (`ORD-123456`), describe what the tool returns, and say which tool to call first ("Call this before orders_refund"). To test it, collect 20–30 real requests, label the expected tool, run each several times with the tool order shuffled, change one description at a time, and read the confusion matrix. Why it matters: it's the other half of Code Mode (11-20). Fewer and clearer tools mean fewer tokens and fewer wrong picks. Who: anyone with more than 3 MCP servers in Claude Code. Action: see Top Thing.

**WORKFLOW — Evaluating an agent after launch: answer eval, path eval and live sampling, plus the three silent changes that break a working agent.** Source: The Nuanced Perspective (Chai & AI session led by Jacob Chacko). Worked example: a B2B dispute agent handling 4,000 disputes a month at about €1,200 each, close to €5M a month. The pilot ran on 300 historical disputes with a 92% match-the-analyst launch gate. The three silent changes: (1) the provider swaps the model behind an alias and the agent returns "pricing error" instead of the code `PRICE_ERR`, (2) someone adds "Be flexible with strategic customers" to the prompt when 40% of customers count as strategic, (3) finance changes the invoice format and the agent credits the same discount twice. The setup: build cases from 12 months of real decisions, keep at least 25% of them edge cases, have two analysts double-check each expected outcome, run the full suite every night and on every model, prompt or data change, pin the dated model ID instead of "latest," and each week have an analyst decide 50 live cases without seeing the agent's answer. Their cost model: €50,608 in year one and €32,668 a year after, with a 1.5x avoided-loss hurdle. The low-volume case (1,500 disputes at €800) doesn't clear it, so it gets live sampling only. Why it matters: a dashboard can stay green while the agent's judgment gets worse. Who: anyone with an agent running on a schedule, including this routine. Action: write down this routine's three change triggers (model, prompt, inbox mix) and keep 5 past digests as a regression set.
