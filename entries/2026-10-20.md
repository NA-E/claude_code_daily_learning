**NEWS — Supabase stops auto-granting Data API access to new "public" tables on October 30.** Source: Supabase "Final notice" email (noreply@supabase.com). From October 30 (10 days from today), any table created in `public` needs an explicit GRANT before supabase-js, PostgREST or GraphQL can reach it; otherwise the API returns "permission denied" with the statement to run. Existing tables keep their grants. It also hits migrations that recreate your schema: new projects, preview branches and local `supabase db reset`. Fix, in the same migration that creates each table: `grant select on public.your_table to anon;` `grant select, insert, update, delete on public.your_table to authenticated;` `grant select, insert, update, delete on public.your_table to service_role;`. Details: github.com/orgs/supabase/discussions/45329. Why it matters: new tables will silently break the first request after Oct 30. Who: anyone with a Supabase project (this follows 10-14's RLS alert). Action: see Top Thing.

**CONCEPT — Agent context bloat: a memory pointer cut 252,000 tokens to about 9,000 across eight log fetches.** Source: The Neuron "AI Skill of the Day", citing AWS's Elizabeth Fuentes Leone (youtube.com/watch?v=DrfyORO8RqA) and Chew Loong Nian's re-test in AWS Strands. The fix: store big tool output outside the conversation and give the agent a short ID. Second fix: cap repeat calls and give a clear "done" signal; one agent went from 14 repeat calls to 2. Caveat: the test measures context size, not answer quality. Prompt: "Review my agent for tools that can return large outputs (logs, search results, files). For each one: (1) save the full output to a file and return only a short summary plus a file ID, (2) set a maximum number of calls per tool per task, and (3) add a clear 'done' condition so the agent stops once it has an answer." Who: anyone running Claude Code or custom agents. Action: paste that prompt against your routine's own tool calls.
