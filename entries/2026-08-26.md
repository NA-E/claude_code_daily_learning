**WORKFLOW — Every.to published its actual recipe for building a task-specific eval instead of trusting public benchmarks.** Source: Every.to, "Benchmarks Don't Know Your Job." The concrete method: pick one recurring job (a weekly report, a slide deck), write down 5 ways the current model gets it wrong with one gold-standard example each, then run every model you're considering against those 5 cases. Backing data: Mercor CEO Brendan Foody says he regularly meets execs spending $100M/year on models with zero offline evals; Vercel CEO Guillermo Rauch's own chart shows open-source models going from 28% to 62% of token share on Vercel's frontend cloud in two months. Reliability caveat from the same issue: arxiv paper "Thinkingbox" (arxiv.org/abs/2608.19741) found the strongest coding model passing 65% of single attempts, but only 25% when required to succeed on 20 consecutive attempts in a row.

**CONCEPT — Every's own KateBench eval shows exactly how an 85-90% "acceptance rate" can lie to you.** Source: same Every.to issue. KateBench is an AI copyeditor trained on ~30,000 of editor-in-chief Kate Lee's past edits; editors accept 85-90% of its suggestions in a Google Doc. Engineer Jannik Jung found two hidden problems: the tool capped out at 40 suggestions per doc (silently discarding good edits on long essays past that point — the cap is now raised to 80), and the tool doesn't produce identical edits on repeat runs, so the acceptance rate moves even when nothing about the model changed. Takeaway for any eval you build: a single good score from one run isn't a signal, run it several times before trusting a change was real.
