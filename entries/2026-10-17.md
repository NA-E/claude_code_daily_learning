**FEATURE — Per-subagent effort level, since Claude Code v2.1.292.** Source: Anthropic, "This week in Claude Code". Set effort in the prompt and it overrides the session level for that subagent, for example: `Find every payments API call with low effort subagents, then have a high effort one check the error handling`. Before v2.1.292 this needed effort in a custom subagent's frontmatter. You can name a model the same way (Haiku for quick lookups). Engineering tip from the same email: adding "Time matters here: do not spend time that can be avoided, and the earlier a correct result is obtained, the better" changes how subagents pace themselves. Why it matters: it is the practical answer to 10-16's 18x effort spread. Who: anyone running multi-step Claude Code tasks. Action: see Top Thing.

**FEATURE — Idle compaction and `/usage` warnings in v2.1.299.** Source: Anthropic, "This week in Claude Code" (code.claude.com/docs/en/changelog#2-1-299). A terminal session over 200K tokens that sits idle is compacted just before the one-hour prompt cache expires, so you reprocess only the summary when you return. Turn it off with `"idleCompaction": false` in settings.json. `/usage` now warns about max effort, workflows, always-on context and large tool results. Why it matters: it saves usage on forgotten long sessions, and the warnings point at the 10-14 and 10-16 cost themes. Who: heavy terminal users. Action: run `claude update`, then `/usage` once and read the warnings.

**FEATURE — Hooks can block on failure (v2.1.295) and run before skills expand (v2.1.299).** Source: Anthropic, "This week in Claude Code" (code.claude.com/docs/en/changelog#2-1-295). Set `"onFailure": "block"` on a command or HTTP hook, and a hook that cannot start, times out or exits with an unexpected code blocks the action instead of letting it through. UserPromptSubmit hooks now run before skills and slash commands expand; if the hook blocks, the shell commands inside the skill do not run. Why it matters: before this, a broken safety hook failed open. Who: anyone using hooks as guardrails. Action: add `"onFailure": "block"` to any hook whose job is to stop something.
