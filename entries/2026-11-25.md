## Top Thing to Implement Right Now

**ONE ACTION → Turn on Row-Level Security for the exposed table in your Supabase project "Chris" → DO TODAY.**

**HIGH LEVERAGE:** This is the only item today where the downside is happening right now. Supabase rates it critical: with RLS off on a `public` table, anyone holding the project URL and anon key can read, edit and delete every row. The anon key ships in any frontend that uses the project. The advisor flagged it as of November 22, so it has been open at least 3 days. It takes about 5 minutes.

1. Open supabase.com/dashboard → project `hiooazsxwtkmetiwdbeo` → **Advisors → Security**, and note the table name it lists.
2. In the SQL editor:

```sql
-- see every public table without RLS
select tablename from pg_tables
where schemaname = 'public' and rowsecurity = false;

-- lock the flagged table (replace the name)
alter table public.<table_name> enable row level security;

-- only if the app needs signed-in users to read it:
create policy "authenticated read" on public.<table_name>
  for select to authenticated using (true);
```

3. Re-run the advisor and confirm `rls_disabled_in_public` is gone. If the project is unused, pause it instead.
